**Qué es FT2:** un modo digital de IU8LMC (Martino Merola).
- Su aprobación por ADIF **no está confirmada** (una versión anterior de este manual daba marzo de 2026 como fecha, sin fuente): no la tomes como un hecho.
- Cada ciclo dura **3,75 s**.
- Usa 4-GFSK, LDPC (174,91) y unos 167 Hz de ancho.
- Las frecuencias de dial están en los marcadores 🔢 FT2. En 40 m es **7,052 MHz**.

**El problema:** OpenWebRX+ (1.2.125) **no trae FT2**, y el `jt9` de WSJT-X tampoco lo decodifica.

## Cómo lo hemos integrado (ADR-35)
1. **Decodificador:** `decodium-rx`, el programa de terminal de **Decodium 4.0 «Core Shannon»** (GPLv3, https://github.com/iu8lmc/Decodium-4.0-Core-Shannon).
   - Lo compila `bricohams-ft2 compilar`. Solo compila ese programa, no la interfaz gráfica, pero hacen falta las librerías de desarrollo de Qt6.
   - Tarda 20–40 min en la Pi 5 y ocupa unos 700 MB.
   - **Versión fijada:** compila siempre el commit de `FT2_DECODIUM_REF` (por defecto el que probó el kit), lo comprueba tras descargarlo y lo anota en `/var/lib/bricohams/ft2-decodium.ref`. Si no puede descargarlo, **falla**; nunca compila otra versión en silencio.
   - **Actualizar Decodium:** pon un commit o etiqueta nuevos en `FT2_DECODIUM_REF` (`bricohams.env`) y relanza el paso, o `sudo FT2_DECODIUM_REF=<commit> bricohams-ft2 compilar && sudo bricohams-ft2 activar`. Prueba antes con `bricohams-ft2 probar`.
   - Compilar en Raspberry Pi OS arm64 con Qt 6.4 (Bookworm) **no está confirmado**: el README de Decodium 4.0 pide una Qt más nueva y el script solo parchea `QTimeZone::UTC`.
2. **Adaptador:** `bricohams-ft2-decode` ejecuta `decodium-rx -m ft2 --wav` sobre cada trozo de 3,75 s y **escribe las líneas con el mismo formato que `jt9`**. Así el analizador de FT8/FT4 de OpenWebRX+ las entiende sin cambios: mapa, PSK Reporter y banderas incluidos.
   - **Indicativo (AP):** pasa `--call` con tu `CALLSIGN` (si no es `N0CALL`) para la decodificación con información a priori.
   - **Banda de audio:** `--low 200 --high 5000` por defecto (`FT2_LOW_HZ`, `FT2_HIGH_HZ`), como OpenWebRX+. El valor por defecto de `decodium-rx` es 4000 Hz; si rechazara 5000, baja `FT2_HIGH_HZ`.
   - **Un solo proceso a la vez y plazo corto:** cada trozo tiene como máximo `FT2_TIMEOUT` (3,5 s, siempre < 3,75 s). Si vence, se mata el proceso y el trozo se salta; si el anterior aún corre, el nuevo se salta. Los saltos se anotan en `/var/log/bricohams-ft2.log` (`bricohams-ft2 estado` cuenta los recientes). En una Pi lenta pueden ser frecuentes, porque cada trozo arranca una aplicación Qt entera y no se conserva promediado ni caché AP entre trozos.
   - **Lectura tolerante:** acepta la hora como `HHMMSS`, `HH:MM:SS` o `HH:MM:SS.cc`. El formato exacto de `decodium-rx` lo asumimos, no lo hemos confirmado en todas las versiones.
3. **Parche:** `bricohams-ft2-patch` añade a OpenWebRX+ la clase `Ft2Profile` (ciclo de 3,75 s), el modo `FT2` y «FT2» en el panel de mensajes.
   - Los cambios llevan la marca `BRICOHAMS-FT2`. Se puede repetir y **quitar** (`--quitar`).
   - Un *hook* de apt lo vuelve a aplicar después de cada actualización de `openwebrx`.
   - **¿Admite OpenWebRX+ 3,75 s?** `WsjtProfile.getInterval()` no limita el valor y el formato de nombre `%H%M%S` sirve (intervalo < 60 s), pero el troceador de audio (`owrx/audio/chopper.py`) no forma parte de las copias de prueba y **no hemos confirmado** que no redondee. El parche lo revisa y avisa si ve una conversión a entero. Alternativa que usa la estación: el adaptador no depende del intervalo; toma la hora del nombre del fichero (`…_HHMMSS.wav`) y `decodium-rx` rellena o recorta el audio a un ciclo completo.

## Uso
```bash
sudo bricohams-ft2 estado
sudo bricohams-ft2 compilar     # si el instalador no lo hizo (FT2_ENABLE="yes")
sudo bricohams-ft2 activar
sudo bricohams-ft2 probar       # decodifica el WAV de prueba del kit (una emisión FT2 real: «CQ <indicativo> IM98»)
```
- **En la web:** pulsa un marcador 🔢 FT2 y elige el modo **FT2** en la lista de modos digitales. Los mensajes salen en el panel de FT8/FT4, con bandera.

## Avisos
- **Es experimental:**
  - si una versión nueva de OpenWebRX+ cambia los ficheros, el parche **no se aplica** y lo dice (`bricohams-check` → «FT2 no activo»). El resto de la estación sigue funcionando;
  - el ciclo de 3,75 s exige una hora exacta: el GPS + PPS del HAT con chrony la da.
- **Para quitarlo:** `sudo bricohams-ft2 quitar`, y deja OpenWebRX+ como venía.
